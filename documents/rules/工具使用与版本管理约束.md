# 工具使用与版本管理约束

本文档记录 `paper-rag-assistant` 项目协作过程中的工具使用约束，尤其是版本管理相关约束。

## 适用范围

本规则适用于后续所有围绕 `paper-rag-assistant` 项目的代码修改、文档编写、测试运行、问题排查和工程审查过程。

除非用户在某次对话中明确解除或修改本规则，否则默认持续生效。

## 核心原则

1. 不由 AI 代理执行任何 `git` 命令。
2. 用户自行负责版本管理、变更审查、暂存、提交、回滚和分支操作。
3. AI 代理只负责代码与文档层面的修改、检查、测试和说明。
4. 如果需要查看文件差异，优先使用 PyCharm IDE MCP 服务或普通 PowerShell 文件比对方式。
5. 不主动处理 `.git/index.lock` 等 Git 内部锁文件。

## 禁止事项

AI 代理不得执行任何 `git` 命令，包括但不限于：

```text
git status
git diff
git add
git commit
git reset
git checkout
git restore
git switch
git branch
git merge
git rebase
git stash
git pull
git push
```

注意：

1. 即使是 `git status`、`git diff` 这类通常被视为只读的命令，也不要执行。
2. 当前环境中 `git status --short` 曾触发 `.git/index.lock` 相关提示，因此后续全部避免。
3. 不删除、不移动、不修改 `.git/index.lock`。
4. 不通过其他 shell 命令间接操作 `.git` 目录。

## 可用替代方案

### 文件内容查看

可以使用普通 PowerShell 命令读取文件内容，例如：

```powershell
Get-Content -LiteralPath "app\indexing\vector_collection.py"
```

也可以使用 PyCharm IDE MCP 的文件读取能力，例如：

```text
mcp__pycharm_studio.get_file_text_by_path
```

### 文件差异分析

如果需要比较修改前后的差异，优先使用以下方式：

1. PyCharm IDE MCP 中可用的只读文件读取、问题检查或编辑器能力。
2. PowerShell 的文件读取与文本比较能力。
3. 对关键文件重新读取完整内容，然后在对话中总结变化。

不使用 `git diff`。

### IDE 问题检查

如果需要检查 IDE 报告的问题，可以使用：

```text
mcp__pycharm_studio.get_file_problems
```

该工具只用于读取 IDE 检查结果，不参与版本管理。

## 允许事项

在不触碰 Git 的前提下，AI 代理可以执行：

1. 读取项目文件。
2. 修改项目代码或文档。
3. 运行单元测试。
4. 运行静态检查、格式化或解释器级别检查。
5. 使用 PowerShell 查询目录、文件、文本内容。
6. 使用 PyCharm IDE MCP 读取文件、检查问题或辅助定位代码。

## 修改后的说明要求

每次完成代码或文档修改后，AI 代理应在最终回复中说明：

1. 修改了哪些文件。
2. 完成了什么行为。
3. 运行了哪些测试或检查。
4. 是否存在未验证内容。
5. 如果涉及版本管理，明确说明未执行任何 `git` 命令。

## Git 锁文件处理

如果发现 `.git/index.lock` 存在：

1. AI 代理只报告发现结果。
2. AI 代理不删除该文件。
3. AI 代理不尝试修复 Git 状态。
4. 用户自行判断是否关闭 IDE、终止 Git 进程或手动清理锁文件。

## 约束目的

这条约束的目的不是禁止版本管理，而是保持职责边界清晰：

```text
AI 代理：实现、解释、测试、文档整理
用户：审查、暂存、提交、回滚、分支管理
```

这样可以避免 AI 代理无意触发 Git 锁文件、改变暂存区状态，或影响用户正在进行的版本管理流程。
