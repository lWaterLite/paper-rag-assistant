# 运行时生命周期

## 职责边界

```text
ApplicationFactory
  读取 Settings、注册表与依赖关系
  组装 ApplicationRuntime

ApplicationRuntime
  启动时加载一次持久化 RagIndex
  创建并缓存 SearchService、CompareSearchService、RagPipeline
  关闭时清空运行期对象引用

RuntimeManager
  管理多个 Runtime 的启动顺序和关闭顺序
  启动顺序：注册顺序
  关闭顺序：注册顺序的反向
```

`Factory` 不持有在线索引或请求服务；`Runtime` 不解析外部 Settings 或自行创建
Factory。这使离线索引构建、命令行调用和未来 Web 服务具有清晰边界。

## 在线启动流程

```text
ApplicationFactory.build_runtime()
  -> ApplicationRuntime
  -> RuntimeManager.register(application_runtime)
  -> RuntimeManager.start()
  -> ApplicationRuntime.start()
  -> IndexLoader.load()
  -> 创建 SearchService / CompareSearchService / RagPipeline
  -> RuntimeState.RUNNING
```

在线请求只读取 Runtime 中已创建的对象：

```text
HTTP Route
  -> 注入 application_runtime.search_service
  -> handle_search_request(request, search_service)
```

Handler 不应调用 `ApplicationFactory`、`IndexLoader`、Repository 或 Builder。

## Web 框架适配

`create_web_lifespan(manager)` 返回一个接收应用对象、返回异步上下文管理器的函数。
它不依赖 FastAPI；采用相同约定的框架可以直接复用。

FastAPI 接入时的组合方式如下：

```python
factory = ApplicationFactory(...)
manager = RuntimeManager()
manager.register(factory.build_runtime())
app = FastAPI(lifespan=create_web_lifespan(manager))
```

Route 中应从应用依赖注入层取得 `ApplicationRuntime`，再读取所需 Service。不要在
每个请求中启动 Runtime，也不要在 Route 内部重新加载持久化索引。

## 扩展规则

未来出现需要进程级管理的组件时，例如连接池、后台索引任务协调器、缓存预热器或
外部模型客户端，可实现 `Runtime` 协议并注册到同一个 `RuntimeManager`。需要依赖
Application Runtime 的组件应在它之后注册，以保证关闭时先释放依赖方。
